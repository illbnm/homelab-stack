# Notifications Stack

Unified notification center for HomeLab Stack. Provides three complementary notification services so all homelab services can push alerts to your phone, desktop, or chat apps.

## What's Included

| Service | Version | URL | Purpose |
|---------|---------|-----|---------|
| Gotify | 2.5 | `gotify.<DOMAIN>` | Self-hosted push notification server with web UI |
| ntfy | 2.11 | `ntfy.<DOMAIN>` | HTTP pub-sub notifications with mobile apps |
| Apprise | 1.1.6 | `apprise.<DOMAIN>` | Multi-channel relay (Discord, Slack, Telegram, Email, etc.) |

## Quick Start

```bash
# 1. Copy environment template and fill in values
cd stacks/notifications
cp .env.example .env
# Edit .env — set GOTIFY_PASSWORD at minimum

# 2. Link root .env for DOMAIN and TZ
ln -sf ../../.env .env.shared 2>/dev/null || true

# 3. Start all services
docker compose up -d

# 4. Wait for services to be healthy (30-60 seconds)
docker compose ps

# 5. Run setup script (creates ntfy user, Gotify app, sends test)
cd ../..
./scripts/notify-setup.sh
```

## Configuration

### Environment Variables

**`stacks/notifications/.env`**

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `GOTIFY_DEFAULTUSER` | No | `admin` | Gotify admin username |
| `GOTIFY_PASSWORD` | **Yes** | — | Gotify admin password (set before first start) |
| `NTFY_AUTH_ENABLED` | No | `true` | Enable ntfy authentication |
| `NTFY_TOKEN` | Auto | — | Auto-generated by `notify-setup.sh` |
| `NTFY_USER` | No | `homelab` | ntfy service account username |
| `NTFY_PASSWORD` | Auto | — | Auto-generated if not set |
| `GOTIFY_TOKEN` | Auto | — | Auto-generated by `notify-setup.sh` |

**Root `.env` (shared by all stacks)**

| Variable | Required | Description |
|----------|----------|-------------|
| `DOMAIN` | **Yes** | Base domain (e.g. `home.example.com`) |
| `TZ` | **Yes** | Timezone (e.g. `Asia/Shanghai`) |

### ntfy Configuration

The ntfy server config is located at `config/ntfy/server.yml`. Key settings:

```yaml
base-url: "https://ntfy.${DOMAIN}"   # Auto-set from DOMAIN
auth-default-access: "deny-all"       # All topics require auth by default
behind-proxy: true                     # Trusts X-Forwarded-For from Traefik
cache-duration: "12h"                  # Messages cached for 12 hours
```

To change ntfy settings, edit `config/ntfy/server.yml` and restart:

```bash
docker compose restart ntfy
```

### Gotify Configuration

Gotify stores its configuration in the database. After first login:

1. Go to `https://gotify.<DOMAIN>` and log in with admin credentials
2. Create a new application in **APPS → + CREATE APP**
3. Copy the application token for use in `scripts/notify.sh` or external services

### Apprise Configuration

Apprise supports 100+ notification services. Configure notification URLs via:

1. Web UI: Go to `https://apprise.<DOMAIN>` and add service URLs
2. Config file: `/config/apprise.yaml` inside the container volume

Example Apprise config:

```yaml
urls:
  - discord://webhook_id/webhook_token/
  - slack://tokenA/tokenB/tokenC/
  - telegram://bot_token/chat_id/
  - mailto://user:pass@smtp.example.com
  - gotify://gotify.<DOMAIN>/gotify_token/
```

Apprise URL format reference: https://github.com/caronc/apprise/wiki#notification-services

## Service Integration Guides

### Watchtower (Container Update Notifications)

Add to your `.env`:

```bash
WATCHTOWER_NOTIFICATIONS=ntfy
WATCHTOWER_NOTIFICATION_URL=https://ntfy.${DOMAIN}/homelab-updates
WATCHTOWER_NOTIFICATION_TOKEN=<your-ntfy-token>
```

### Alertmanager (Prometheus Alerts)

The Alertmanager config (`config/alertmanager/alertmanager.yml`) includes a pre-configured ntfy webhook receiver. Enable it:

```yaml
receivers:
  - name: ntfy
    webhook_configs:
      - url: 'http://ntfy:80/homelab-alerts'
        send_resolved: true
```

Update the default receiver:

```yaml
route:
  receiver: ntfy    # Change from 'default' to 'ntfy'
```

### Gitea (Repository Notifications)

Go to Gitea **Settings → Notifications** or use webhooks:

1. Go to `https://gitea.<DOMAIN>/user/settings/hooks`
2. Add a new webhook:
   - **Target URL:** `https://ntfy.<DOMAIN>/homelab-gitea`
   - **Content Type:** `application/json`
   - **Trigger:** Choose events (push, issues, PRs)
3. Set **Authorization** header to `Bearer <ntfy-token>`

### Home Assistant

Use ntfy's built-in integration:

1. In HA, go to **Settings → Devices & Services → Add Integration**
2. Search for "ntfy"
3. Configure:
   - **Server:** `https://ntfy.<DOMAIN}`
   - **Topic:** `homelab-ha`
   - **Token:** your ntfy auth token

### Uptime Kuma

1. Go to **Settings → Notifications → Setup Notification**
2. Select **ntfy** type
3. Configure:
   - **ntfy Server URL:** `https://ntfy.<DOMAIN}`
   - **ntfy Topic:** `homelab-uptime`
   - **Priority:** 5
   - **Headers:** `Authorization: Bearer <ntfy-token>`

### Jellyfin / Sonarr / Radarr

For media stack notifications, use the Gotify webhook:

1. In the service settings, add a notification webhook
2. **URL:** `https://gotify.<DOMAIN>/message?token=<GOTIFY_TOKEN>`
3. **Method:** POST
4. **Body (JSON):**
   ```json
   {
     "title": "{event}",
     "message": "{description}",
     "priority": 5
   }
   ```

## Unified Notification Script

`scripts/notify.sh` is the single entry point for all notifications. Other scripts and services should call this instead of directly hitting ntfy/Gotify APIs.

```bash
# Basic usage
./scripts/notify.sh <topic> <title> <message> [priority]

# Examples
./scripts/notify.sh homelab-test "Test" "Hello World"
./scripts/notify.sh backups "Backup Complete" "All services backed up successfully" high
./scripts/notify.sh alerts "CPU Alert" "Server CPU at 95%" urgent
```

**Priority levels:** `min` | `low` | `default` | `high` | `urgent`

The script sends to:
1. **ntfy** (primary) — always attempts
2. **Gotify** (relay) — if `GOTIFY_TOKEN` is configured
3. **Apprise** (multi-channel) — always attempts (non-fatal if Apprise has no services configured)

## Troubleshooting

### ntfy Web UI not loading

- Verify Traefik is running and `proxy` network exists
- Check container health: `docker compose ps`
- Check Traefik dashboard: `https://traefik.<DOMAIN>`
- Review ntfy logs: `docker logs ntfy --tail 50`

### Cannot send notifications (401 Unauthorized)

- ntfy has auth enabled by default (`auth-default-access: deny-all`)
- Create a user: `docker exec ntfy ntfy user add myuser mypassword`
- Generate a token: `docker exec ntfy ntfy token create myuser`
- Set `NTFY_TOKEN` in `stacks/notifications/.env`

### Gotify shows wrong time

- Set `TZ` in root `.env` (e.g., `TZ=Asia/Shanghai`)
- Restart Gotify: `docker compose restart gotify`

### Apprise not sending to external services

- Apprise needs service URLs configured to know where to send
- Add notification URLs via the web UI or config file
- Check Apprise logs: `docker logs apprise --tail 50`

### Watchtower not receiving ntfy notifications

- Verify `WATCHTOWER_NOTIFICATION_TOKEN` matches your ntfy token
- ntfy topic must exist: `curl -X POST https://ntfy.<DOMAIN>/homelab-updates -d "test"`
- Check Watchtower logs: `docker logs watchtower --tail 50`
